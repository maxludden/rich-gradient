# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`rich-gradient` is a renderable library for [Rich](https://github.com/Textualize/rich) that layers smooth foreground/background gradients on top of Rich renderables (text, panels, rules, markdown, tables, trees, etc.), including animated variants. As of v0.3.12 the CLI was split out into the sibling package [`rich-gradient-cli`](../rich-gradient-cli) — this repo is the core renderable library only; there is no `cli.py` here anymore.

## Commands

Use `uv` for everything — do not use bare `pip`/`python`.

- Install: `uv sync`
- Run all tests: `uv run pytest`
- Run a single test file/case: `uv run pytest tests/test_gradient.py -k test_name`
- Run benchmarks: `uv run pytest tests/benchmark_perf.py`
- Type check: `uv run mypy`
- Build docs locally: `uv run zensical serve`
- Build docs (CI check): `uv run zensical build --clean`
- Build wheel: `uv build`

`tests/conftest.py` inserts `src/` onto `sys.path`, so tests run against the working tree without an editable install.

Before committing, run `uv run pytest` and `uv run zensical build --clean` — CI expects both to pass with no extra environment variables.

## Architecture

- **`gradient.py`** (`Gradient`) is the core wrapper: it takes any Rich `ConsoleRenderable` and injects per-character gradient/highlight styling. Panels, rules, markdown, and table/tree/columns/pretty/syntax wrappers are all built on top of this.
- **`text.py`** (`Text`) subclasses `rich.text.Text` directly rather than wrapping — use it when you want a drop-in `Text` replacement with gradient spans baked into the text itself.
- **`animated_*.py`** modules (`animated_gradient.py`, `animated_panel.py`, `animated_text.py`, `animated_rule.py`, `animated_markdown.py`) wrap `rich.live.Live` for live-updating gradients. They all consult `config.animation_enabled` — keep that wiring intact when touching animation flags.
- **`config.py`** (`RichGradientConfig`) merges defaults, `~/.rich-gradient/config.json`, and env vars (e.g. `RICH_GRADIENT_HOME_DIR`, `RICH_GRADIENT_COLORS`) via `_deep_update`. When adding a config option, update `RichGradientConfig.DEFAULT_CONFIG` and make sure both the JSON and env-var override paths reach it. `reload_config()` in `__init__.py` refreshes the package-level `config`/`CONFIG` aliases — tests that touch config (`test_config.py`) rely on this hook rather than reimporting the module.
- **`_color_ext.py`** auto-installs `rich_color_ext` at import time (`__init__.py` calls `rc_install()` if not already installed). Avoid adding new top-level import-time side effects — they can trigger circular imports here.
- **`spectrum.py`** (`Spectrum`) generates reproducible color stops/palettes (seedable) used by the rainbow-gradient code paths. `validate_hues` enforces the shared `hues >= 2` minimum for `Spectrum`, `Text`, and `Gradient`.
- **`repeat_scale`** defaults to `None` on `Gradient` and the static wrappers; `Gradient._ramp_stops()` derives it from the color stops (1.0 for two colors, 2.0 for three or more, mirroring background stops to match) so the first and last colors are both reached. The animated classes keep explicit defaults.
- **`_gradient_ramp.py`** provides a cached gradient ramp so foreground/background styles are precomputed per render span and reused across segment lookups (perf-sensitive; covered by `tests/benchmark_perf.py`).
- **`_highlight.py`** implements the highlight-ingestion patterns (`_ingest_init_highlight_*`) shared across `Gradient` and related renderables — both mappings and sequences of highlight rules are accepted; follow the existing patterns there rather than re-parsing highlight args ad hoc.
- Color/style inputs are normalized rather than restricted to one format: CSS names, hex strings, RGB tuples, and `rich.color.Color` objects should all work anywhere a color is accepted. Reuse `Text._normalize_color` / `Gradient._to_color_triplets`, which parse strings through `_color_ext.parse_color` (Rich's parser first, `rich-color-ext` as the fallback), instead of writing new parsing. Names Rich defines keep Rich's meaning, so `"red"` is ANSI red, not CSS red.
- Gamma-correct interpolation (`_GAMMA_CORRECTION = 2.2` in `gradient.py`) is load-bearing for the tests — several assertions in `tests/test_gradient.py` are pinned to this value; don't change it without updating the whole gradient-math test suite.

## Docs & assets

- `docs/*.md` + `zensical.toml` build the published site with [Zensical](https://zensical.org) (the project moved off MkDocs; there is no `mkdocs.yml`). Output goes to `site/`, a build artifact — don't hand-edit it. Theme tweaks live in `docs/stylesheets/`. Pushes to `main` publish the site to GitHub Pages via `.github/workflows/docs.yml`; `zensical build` itself never deploys.
- Docs SVGs are generated by scripts in `examples/`; regenerate them before committing if you change rendering behavior, or CI-published docs will show stale screenshots.
- When changing a public API, update `docs/*.md` and the corresponding `examples/*.py` together so docs and screenshots stay in sync.
